# 待完成项

本文件是《Voxeldustry 插件化架构方案》对照当前代码的剩余工作清单。基线是 commit `8cf0bde`；已落地的插件注册表、存档冻结、Custom 载荷、只读打开、目录式包、BMS Lua 加载、运行期校验和不再重复。技术债与环境限制见 [[11-当前状态与风险]]。

排序原则：**先把「建档 → 玩 → 存档 → 再打开」的产品闭环补齐，再做玩法内容，最后做联机与深度 Mod 能力。** 底层机制已经领先于内容，继续只补底层不会产生可玩的东西。

## P0：三块产品闭环（当前里程碑）

### P0-3 只读差异面板

只读模式已经能打开不同身份的存档，但玩家看不到差异。当前没有 `compute_load_diff`，也没有差异 UI。

- [ ] `compute_load_diff` 只在 `LoadMode::ReadOnly` 下比较：存档 `plugins` / `actions` / `params` 对当前 `ActivePlugins` / `ResolvedActions` / `ParamTable`。
- [ ] 差异分类：缺失插件、多余插件、顺序不同、动作表不同、参数不同；每项给出可读名字，不只给 id。
- [ ] `WorldLoadDiff` 进 `StreamingDiagnostics` 快照，读档完成后可轮询。
- [ ] FFI `get_world_load_diff()`；无差异返回空，不返回 `null`。
- [ ] GDScript `ReadOnlyDiffPanel`：分组列表 + 「以只读方式继续」/「返回」；只读模式禁止存档、tick、输入。
- [ ] `bevy_client` 在读档完成后发 `world_load_diff_ready`，UI 不靠固定延时猜时机。
- [ ] 测试：身份完全一致（空差异）、缺插件、多插件、顺序不同、动作表不同、参数不同。

**验收**：正常档打开不弹面板；只读档一定能看到「差在哪」，且不会误写存档。

## 明确不做 / 已接受

- 发布前不做旧档兼容：缺 `actions` / `plugins` 段一律按坏档拒绝，不写迁移。
- BMS 脚本系统暂缓：只保留脚本加载与组件，不接 `ScriptSystemBuilder`。
- 不支持 native dylib mod：Rust 无稳定 ABI，跨 `.so` 传 `&mut App` 不可行。
- 不做 zip 包：目录式包是当前唯一格式，除非有明确分发包需求。
- 不承诺反作弊：验证只证明「这台机器这一次确定」，运行期校验和保留但可采样。
