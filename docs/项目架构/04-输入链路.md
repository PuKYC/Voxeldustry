# 输入链路

## 分层

```text
Godot 物理输入
  → GDScript 采集：只查 InputMap 名，不做语义判断
  → godot-client-ext 机械转换：Variant → RawInputFrame
  → InputStaging：last-wins + 边沿锁存，跨线程合并
  → 输入系统链：折叠 / 控制关系 / 能力过滤 / 历史 / 事件
  → 玩法系统消费 ResolvedInput
```

引擎只提供与动作表无关的骨架，动作表由 `ActionMap` 注入。

## 动作表与通道

| 概念 | 类型 | 说明 |
| --- | --- | --- |
| 动作 | `ActionDef` / `ActionId` | 名字映射到位号 |
| 动作表 | `ActionMap`，本游戏是 `CoreActions` | 引擎不写死任何动作名 |
| 通道 | `ChannelMask` / `MAX_INPUT_CHANNELS` | 一个控件形态覆盖多个动作位 |
| 来源 | `InputSourceId` | 多设备与多输入源，默认 0 |

`godot-client-ext` 把动作表与通道表导给 Godot，按键绑定留在 GDScript，`game-core` 不持有物理键。

### 本游戏动作表（`ACTION_TABLE`）

唯一真相源是 `game-core/src/input/actions.rs`；`ActionId` 是语义标识，
`bit` 才是输入通道位（存档 / 协议 / 回滚只看位）。

| 动作 | ActionId | 通道位 |
| --- | --- | --- |
| `move_forward` | 1 | bit 0 |
| `move_back` | 2 | bit 1 |
| `move_left` | 3 | bit 2 |
| `move_right` | 4 | bit 3 |
| `jump` | 5 | bit 4 |
| `glide` | 6 | bit 5 |
| `flight_toggle` | 7 | bit 6 |
| `interact` | 8 | bit 7 |
| `attack` | 9 | bit 8 |
| `break_block` | 10 | bit 9 |
| `sprint` | 11 | bit 10 |
| `crouch` | 12 | bit 11 |
| `reload` | 13 | bit 12 |
| `drop_item` | 14 | bit 13 |
| `place_block` | 15 | bit 14 |

### mod 动作表（`ResolvedActions`）

静态 `ACTION_TABLE` 是 core 的动作表；mod 可以在 `ModManifest.actions` 里声明额外动作。装配时 `Mods::apply` 调 `ResolvedActions::resolve(core, mods)` 解析出一张全局表并注入 App：

- core 动作保持原 id / 通道位；
- mod 动作按 `(mod_id, name)` 排序后分配 `ActionId = 1000 + 序号` 与从 0 起第一个空闲通道位（core 占 0..=14，因此从 bit 15 起；上限 64）；
- 重名（与 core 或 mod 之间）、非法名字、id / 通道位耗尽都让装配失败。

输入系统在有 `ResolvedActions` 时用它（`action_of_bit` / `from_names_with_table`），没有则回退静态 `ActionMap`，因此无 mod 时逐位行为不变。这张表在建档时冻结并随存档保存，读档阶段一与当前装配逐项比对，详见 `08-静态数据与Mod体系.md`。

mod 动作位在实体上用 `ModActionChannel(u64)` 声明：`ChannelSet.extra` 直接进 `present`，但 `compute_input_availability` 会先滤掉其中的核心位（mod 不能借它开核心动作）；`Stunned` / `Rooted` 不削减 mod 位，`InputDisabled` 削减。

Godot 线程拿不到 `World`，所以后端装配成功后把解析结果发布到进程级全局表（`publish_active_actions` / `active_actions`），`get_action_table()` 与 `submit_input_frame()` 都读它。`BevyClient` 在 `bev_started` 时调 `BevyInput.refresh_actions()` 补注册一次：`setup()` 跑在 Bevy 启动之前，那时只有核心表，mod 动作要等后端装配完成才可见（已存在的动作不覆盖，尊重改键）。

`attack` / `break_block` / `place_block` 是三个**互相独立**的语义动作与通道，
不存在聚合的 `tool` 通道，也没有 `primary_tool` / `secondary_tool`：能力组件与
禁用状态可以分别门控它们，玩法系统也分别解释意图。

### 输入通道表（`INPUT_CHANNEL_TABLE`）

顺序固定（Godot 按此顺序遍历），只描述「通道由哪些动作组成、用哪种控件呈现」，
不含物理按键。

| 通道 key | 动作 | 控件形态 |
| --- | --- | --- |
| `move` | `move_forward` / `move_back` / `move_left` / `move_right` | `axis2d` |
| `jump` | `jump` | `button` |
| `glide` | `glide` | `hold` |
| `flight` | `flight_toggle` | `toggle` |
| `interact` | `interact` | `button` |
| `attack` | `attack` | `button` |
| `break_block` | `break_block` | `button` |
| `place_block` | `place_block` | `button` |
| `sprint` | `sprint` | `hold` |

视角（`LookChannel`）不在通道表里：它是独立轴，不占动作位，用
`InputAvailability.look` 单独表达。

## 原始帧与量化

`RawInputFrame` 携带量化后的轴值：

| 数据 | 编码 |
| --- | --- |
| 移动轴 | `AxisI16`，`quantize_axis` 量化，带 `DEFAULT_DEADZONE` |
| 视角 | `quantize_look` 量化，单独走 LookChannel，不占动作位 |
| 按下与松开 | 边沿位，暂存时锁存 |

量化是确定性的一部分：逻辑层拿到整数轴，不依赖浮点精度。

## 暂存区

`InputStaging` 是 Godot 与 Bevy 之间唯一的输入缓冲：

- 每个 `InputSourceId` 保留最新一帧，旧帧被覆盖。
- 按下与松开边沿在两次 tick 之间锁存，60 Hz 采样不会丢事件。
- 暂停时 `set_input_suspended(true)`，恢复后从零开始。
- `TickInput` 按 tick 取走并清零。

## 系统链

| 顺序 | 系统 | 作用 |
| --- | --- | --- |
| 1 | `advance_simulation_tick` | `SimulationTick` 自增 |
| 2 | `ingest_raw_input` | 暂存区到折叠帧 |
| 3 | `resolve_controlled_entity` | 找到本地控制实体 |
| 4 | 游戏侧 `InputSet::Availability` | 按能力裁剪可用位 |
| 5 | `write_resolved_input` | 写 `ResolvedInput` |
| 6 | `record_input_history` | 写 `InputBuffer`，预测与回滚用 |
| 7 | `derive_input_events::<A>` | 派生瞬时事件 |

### 只读会话（`ReadOnlySession`）

`ReadOnlySession`（`game-engine/src/input/mod.rs`，`game-core` 重导出）是一个资源开关：`InputPlugin::build` 在初始化资源、配置集合之后检查到它，就直接返回，**不注册**上表 1–7 的 `FixedPreUpdate` 链。后果是 `SimulationTick` 不增、`InputStaging` 不被消费、`ResolvedInput` / `InputBuffer` / 输入事件都不再产生；`FixedUpdate` 本身照跑，表现层继续按既有实体快照渲染。

只读会话的装配由 `BevyBackendConfig.read_only` 驱动：插件选择走 `readonly_plugin_selection()`（剔除会推进玩法状态的插件），存档走 `SavePaths::read_only`，读档走 `LoadMode::ReadOnly`。三者只在「看世界」这一个入口同时打开，详见 `08-静态数据与Mod体系.md`。

## 数据与事件

| 类型 | 用途 |
| --- | --- |
| `ResolvedInput` | 本 tick 最终输入，玩法系统只读它 |
| `PlayerInput` | 预测与回滚重演用的输入 |
| `InputBuffer` | 按 tick 的输入历史 |
| `InputActionPressed` / `InputActionReleased` | 瞬时动作事件 |
| `InteractRequest` | 交互请求，带目标 id |
| `InteractionHint` | 交互提示：`action` / `enabled` / `target`（0 无目标、1 实体、2 方块） |

## 能力回传

能力状态经 `INPUTCAPS` 载荷回到 Godot：

| 字段 | 含义 |
| --- | --- |
| `present` | 能力组件并集 |
| `available` | 经禁用削减后的可用位 |
| `source` | `ControlledBy.source`，0 表示无控制源 |
| `local` | 是否挂 `LocalPlayer` |

`present` / `available` 都是 64 位通道位掩码，位序完全由 `ACTION_TABLE` 的
`channel_bit` 决定（当前最高用到 bit 14）。**位布局随动作表变化**，Godot 侧要用
`get_input_channels()` 导出的 `actions` 反查通道，不能写死位号；存档 / 回滚 /
协议也只在动作表内部版本间保持位号稳定。

GDScript 的 `BevyInputContext` 订阅后转发 `input_capabilities_changed` 与 `input_look_changed` 信号，UI 用它们决定控件显隐。

## 触屏输入

触屏不新增输入链路，只把触摸翻译成已有的 InputMap 动作与视角位移，Rust 侧零改动：

```text
InputEventScreenTouch / ScreenDrag
  → UI 触屏控件层（godot-project/ui/touch/）
     ├ 摇杆：Input.action_press(action, strength) / Input.action_release(action)
     └ 视角区：累计 ScreenDrag.relative → BevyInput.on_look_delta(delta)
  → 动作按钮（godot-project/ui/input/ActionButtonHost → ui/widgets/ActionButton）
     按 ButtonSpecs 的 action 注入 Input.action_press / action_release
  → BevyInput.collect_and_submit()：held / pressed / released + get_vector + look_delta
  → submit_input_frame() → InputStaging（与键鼠完全同一条路）
  → 量化、能力过滤、事件派生（Rust 不变）
```

| 触摸控件 | Godot 落点 | Rust 落点 |
| --- | --- | --- |
| 虚拟摇杆 | `Input.action_press("move_forward", strength)` 等 `move_*` 动作 | `get_vector` 合成移动轴 → `quantize_axis` |
| 视角区 | `InputEventScreenDrag.relative` 累计后 `BevyInput.on_look_delta()` | 与鼠标位移同一个 `look_delta` → `quantize_look`，走 LookChannel 不占动作位 |
| 动作按钮 | 按 ButtonSpecs 的 `spec.action` 注入 `action_press` / `action_release` | 进 held / pressed / released，与键盘手柄一致 |

关键约定：

- `project.godot` 设 `pointing/emulate_mouse_from_touch=false`，触摸不会再合成鼠标事件；采集层把 `device == InputEvent.DEVICE_ID_EMULATION` 的鼠标移动直接忽略，避免触屏被误判成键鼠。
- 多指按 `event.index` 路由：摇杆只跟第一根手指并按 index 匹配，视角区用 index 集合记录，动作按钮由自绘 `ActionButton` 按 index 归属；三者互不串扰。verifier 实测 Godot 4.7.2 原生 Button 也支持 ScreenTouch 与多指，自绘是释放时机 / per-index / HudWidget 契约的可选增强。
- 动作按钮不是写死的：`get_input_channels()` 的通道表 → `ButtonSpecs` 规格（跳过 `axis2d`，移动归摇杆；缺规格走 `fallback_spec`）→ `ActionButtonHost` 建按钮并注册进托盘；`present` 控制显隐，`available` 控制置灰并立即释放动作。
- 触屏绑定层只按通道 key + 动作名注入 InputMap：`attack` / `break_block` / `place_block` 是三个独立按钮，各自对应 `INPUT_CHANNEL_TABLE` 的一条 `button` 通道；不存在聚合的 `tool` 按钮。
- 隐藏、切走触屏方案、打开菜单、窗口失焦、退出场景树时统一释放：触屏层复位摇杆与视角手势，`ActionButtonHost` 释放按钮动作，避免“手指抬起事件丢失”造成粘键。
- 交互提示的键位文案来自 InputMap 真实绑定（P3b），触屏显示 `Tap`；`INTERACTION` 载荷的 ActionId 不参与反查，其 `target`（0 无目标 / 1 实体 / 2 方块）只用于表现层分类。
- 视角区注入的位移先乘 `look_sensitivity`，并先查 `UiState.accepts_gameplay_input()`，菜单期间不注入。
- `BevyInput` 有两个视角入口：`on_mouse_motion(relative)`（`BevyClient._input` 转发的鼠标位移）与 `on_look_delta(delta)`（UI 注入的触屏位移），两者都累加进同一个 `_look_accum`，每帧取走并清零。
- 暂停与菜单期间不提交玩法输入：`BevyClient._process` 只 `UiState.accepts_gameplay_input()` 为真时调 `collect_and_submit()`，见 [[10-Godot-UI方案]]。

输入方案（触屏 / 键鼠 / 手柄）由 `UiRoot` 检测并写入 `UiState.scheme`，只影响 HUD 与相机策略；采集链路不区分来源，也不因方案变化改行为。

## 新增一个动作的步骤

1. 在 `game-core/src/input/actions.rs` 的 `ACTION_TABLE` 里加一项：分配**唯一的
   `ActionId` 与通道位**（`bit < MAX_INPUT_CHANNELS`）。已有位号不可复用/挪动，
   否则破坏存档 / 回滚 / 协议兼容。
2. 需要能力门控就在 `game-core/src/input/capability.rs` 加通道动作常量 +
   `simple_channel!` 通道类型 + 对应 `*_mask()`，并挂进 `INPUT_CHANNEL_TABLE`；
   同时在 `ChannelSet` / `channel_mask` / `compute_input_availability` 里声明该能力。
3. 需要禁用语义就挂进 `stunned_mask` / `rooted_mask`（例如眩晕削减攻击、破坏、放置）。
4. 在 GDScript 侧给 InputMap 加默认按键，或交给玩家改键。
5. 要出触屏按钮就在 `godot-project/ui/input/button_specs.gd` 的 `BY_CHANNEL` 加规格（不加则走 `fallback_spec` 兜底）。
6. 玩法系统从 `ResolvedInput` 读位，不直接读物理键。
