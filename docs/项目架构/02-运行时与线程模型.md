# 运行时与线程模型

## 两个线程

| 线程 | 做什么 | 禁止 |
| --- | --- | --- |
| Godot 主线程 | GDScript 表现层、`BevyAppManager` 的全部节点方法 | 直接跑 Bevy 系统，跨线程持有 `Gd<T>` |
| Bevy 后台线程 | `game-engine::backend::run_headless` 里的 `App` | 碰任何 Godot 类型 |

`godot-rust` 的 `Gd<T>` 是 `!Send + !Sync`，节点方法只能主线程调用。后台线程只通过 `ClientBridge` 的 `Arc` 句柄交换纯数据。

## ClientBridge 的四个句柄

| 字段 | 类型 | 方向 |
| --- | --- | --- |
| `input` | `InputStaging` | Godot 写、Bevy 读 |
| `slot` | `PresentationSlot<S::Payload>` | Bevy 写、Godot 取 |
| `events` | `PresentationEventQueue<S::Event>` | Bevy 推、Godot drain |
| `semantics` | `S::Semantics` | 双方共享，运行期注册 |

四个字段都是 `Arc` 内部的克隆句柄，克隆一次两个线程各持一份。

## 控制与生命周期通道

| 通道 | 类型 | 方向 |
| --- | --- | --- |
| `to_bevy` | `Sender<BevyControlMsg>` | Godot 到 Bevy |
| `from_bevy` | `Receiver<FromBevy>` | Bevy 到 Godot |

`BevyControlMsg`：`Pause`、`Resume`、`Shutdown`、`Custom(String)`。
`BevyLifecycleMsg`：`Started`、`Paused`、`Resumed`、`Error(String)`、`Custom(String)`、`Stopped(i64)`。
`FromBevy { session, payload }` 的 `session` 每次启动自增，Godot 侧据此丢弃上一个线程的残留消息。

## runner 循环

`run_headless` 装配 `MinimalPlugins`、`GameModule`、`Time::<Fixed>::from_hz(fixed_hz)`，然后接管 `set_runner`：

1. 执行一次 `app.finish()` 与 `app.cleanup()`。
2. 每轮先 drain 控制通道，处理暂停与退出。
3. 测出 `delta = now - last_update`，写进 `TimeUpdateStrategy::ManualDuration(delta)`。
4. 调用 `app.update()`。
5. 不足 `1 / runner_hz` 就 sleep 补足。

```text
loop {
    drain ctrl channel
    if paused { sleep 10ms; continue }
    delta = now - last_update
    TimeUpdateStrategy::ManualDuration(delta)
    app.update()
    sleep(target_frame_time - elapsed)
}
```

## 时间与确定性

| 参数 | 来源 | 默认 |
| --- | --- | --- |
| `fixed_hz` | `BevyBackendConfig` 或 GDScript 的 `fixed_hz` | 60 |
| `runner_hz` | 同上 | 60 |

- `FixedUpdate` 每 1/60 秒推进一个 tick，时间由 `ManualDuration(delta)` 累积。
- `runner_hz` 只决定每帧喂多少墙钟时间，不改变单个 tick 的计算。
- 因此帧率变化只改变每帧执行的 tick 数量，同样输入序列得到同样结果。

## 错误与退出

- 后台线程 panic 用 `catch_unwind` 捕获，经通道发 `Error(msg)` 与 `Stopped(1)`，不能让 panic 穿过 FFI。
- 正常退出发 `Stopped(0)`。
- 暂停时 `runner_bridge.set_input_suspended(true)`，恢复时清零，暂停期间的输入不进入模拟。

## 读档拒绝：Started 之后的失败路径

读档发生在 Startup 阶段的 `bootstrap_streaming_world`（exclusive 系统），**晚于**
`run_headless` 已经把 `Started` 发给 Godot、也晚于 `GameModule::build`。所以它
不能用 `ModuleBuildFailure` 那条前置拦截（那条在 `Started` 之前就把 App 装配判死），
必须走「已启动 → 报错 → 停止」的运行时路径：

```mermaid
sequenceDiagram
  participant G as Godot 主线程
  participant R as Bevy 后台线程
  G->>R: Shutdown 之外的控制消息（启动）
  R-->>G: Started
  Note over R: Startup: bootstrap_streaming_world<br/>load_world 返回身份不符
  R->>R: insert WorldLoadRejection / SaveBlocked
  R-->>G: Error{code: "save.missing_mod", message: 中文原因 + path}
  R->>R: world.write_message(AppExit::error())
  R-->>G: Stopped(1)
```

| 环节 | 位置 | 说明 |
| --- | --- | --- |
| 判定 | `game-core/src/world/streaming.rs` `bootstrap_streaming_world` | `SaveErrorKind::is_world_rejection()` 为真才拒绝；截断 / IO / 摘要不符仍按新世界降级 |
| 共享快照 | `WorldLoadRejectionHandle`（`BevyBackendConfig::world_load_rejection`） | `Arc<Mutex<Option<WorldLoadRejection>>>`，App 停掉后 Godot 仍可读 |
| 通道回传 | `BackendChannels::life_tx` | `BevyLifecycleMsg::Error { code, message }`，code 即 `SaveErrorKind::code()` |
| 退出 | `World::write_message(AppExit::error())` | `run_app_loop` 每轮 `app.should_exit()` 读到即退出，并把错误码原样回送 `Stopped(code)` |
| 闸门 | `SaveBlocked` 资源 | 拒绝后所有写盘入口（SaveNow / 自动存档 / 退出补跑帧 / 卸载落盘）直接跳过 |

Godot 侧：`bevy_client.gd` 的 `_on_bevy_error` 把 code 以 `save.` 开头的错误
转成 `world_load_failed(code, message)` 并调用既有 stop 入口；扩展另提供
`world_load_rejection() -> Dictionary`（code / path / message，空字典表示没有），
供差异面板在 `bev_stopped` 之后补读 `path`。

### 只读打开

只读打开走的是同一条「Started 之后读档」路径，区别有三处：

- `BevyBackendConfig.read_only = true` → App 里多一个 `ReadOnlySession`，`InputPlugin` 不注册输入链，`SimulationTick` 冻结；
- 存档路径换成 `SavePaths::read_only(root)`：读档照常，写入口全部拒绝，`SaveBlocked` 之外还有输入层的冻结；
- `load_world_with_mode(..., LoadMode::ReadOnly)` 只放宽身份校验（mod / 动作表 / 插件序列 / 参数），摘要与结构校验照做。

只读**不允许降级**：`world.meta` 缺失、截断、摘要不符、身份不符，全部按拒绝处理，不会「打不开就新建一个空世界」——那会让人误以为存档被重置。拒绝后的收尾与上面完全相同（`BevyLifecycleMsg::Error` + `AppExit` + `Stopped(1)`），差异只在错误 code 与是否写盘。Godot 入口 `start_bevy_streaming_readonly`，GDScript 侧 `bevy_client.gd` 的 `read_only` 与 `open_world_readonly`。

## Godot 侧拉取

`bevy_client.gd` 的 `_process` 每帧：

1. 组装并 `submit_input_frame`。
2. `BevyBridge.take_frame()` 取表现帧，默认走 `take_packed_streams`。
3. `BevyBridge.render_alpha()` 取插值 alpha。
4. 解码并更新节点，`drain_events()` 交给事件路由器。

帧为空表示本 tick 没有新帧。先取再判空，避免对空字节流解析。
