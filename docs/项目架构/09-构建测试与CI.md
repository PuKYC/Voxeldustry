# 构建、测试与 CI

## 本地构建

`bash ./build.sh` 构建 `godot-client-ext` 动态库并复制进 Godot 工程。

| 参数 | 作用 |
| --- | --- |
| 无参数 | 原生 debug |
| `--release` | 原生 release |
| `--target <triple>` | 指定目标三元组 |
| `--all` | 所有已映射平台，任一失败即中止 |
| `--dest <dir>` | 自定义输出根目录，默认 `godot-project/bin` |

环境变量：`CARGO_CMD` 可换成 `cross`，`NDK_ABI` 设置后改用 `cargo ndk`。

产物路径：

```text
godot-project/bin/<debug|release>/<prefix>godot_client_ext_<os>_<arch>.<ext>
```

`main.gdextension` 全部用 `res://bin/<profile>/...` 引用，debug 与 release 分目录存放。

## 运行

用 Godot 4.7.2 打开 `godot-project`，主场景是 `test/node_3d.tscn`。`BevyClient` 的 `mode` 决定启动哪套后端：

| mode | 入口 | 场景 |
| --- | --- | --- |
| `demo` | `start_bevy_with_config` | 实体演示与生产 |
| `voxel_demo` | `start_bevy_voxel_demo` | 体素地形 |
| `voxel_perf` | `start_bevy_voxel_perf` | 体素性能压力 |
| `gameplay_test` | `start_bevy_gameplay_test` | 体素平台与碰撞玩家 |

## 版本固定

| 项 | 位置 | 当前值 |
| --- | --- | --- |
| Rust | 各 workflow 的 `RUST_TOOLCHAIN` 与 workspace `rust-version` | 1.95 |
| Godot | 各 workflow 的 `GODOT_VERSION` 与 `project.godot` 的 features | 4.7.2 |
| GDExtension 最低版本 | `compatibility_minimum` | 4.2 |
| godot crate feature | `godot-client-ext/Cargo.toml` | `api-4-2` |

扩展按 4.2 API 编译，可被 4.2 以上的 Godot 加载，因此兼容旧版无需额外处理。

### UI headless 冒烟

本机没有可用的 Godot 编辑器（headless 编辑器会崩），UI 只做脚本化验证：

```bash
cd /home/dptui/ecs_game && GODOT_BIN=/tmp/Godot_v4.7.2-stable_linux.arm64 tools/ui_check.sh
```

`GODOT_BIN` 指向 Godot 4.7.2 可执行文件，缺省用 `PATH` 里的 `godot`。脚本默认做两件事：

1. 跑 `test/gen_class_cache.gd`，扫描 `class_name` 生成 `.godot/global_script_class_cache.cfg`，并在 `main.gdextension` 存在时写 `.godot/extension_list.cfg`。这两份文件平时由编辑器导入生成，没有编辑器就必须先造出来，否则 `--script` / 场景运行解析不到 `HudWidget`、`UiRoot` 等全局类名，GDExtension 也不会自动启用。
2. 跑 `test/ui_smoke_test.gd`（`extends SceneTree`），失败时非零退出。

可选的第三步是真实场景集成探针（会启动 Bevy 后端，所以要先 `./build.sh` 构建 GDExtension）：

```bash
cd /home/dptui/ecs_game && GODOT_BIN=/tmp/Godot_v4.7.2-stable_linux.arm64 tools/ui_check.sh --gameplay
```

它加载 `test/gameplay_test.tscn`，验证 UiRoot 找到真实 BevyClient、自动注册 3 个 HUD、实例化触屏 / 暂停菜单、CameraRig 入 `camera_rig` 组，以及 `open_pause_menu()` 后 `backend_paused=true`、`camera._ui_blocked=true`，关闭后恢复；通过时打印 `PROBE PASS`。

冒烟覆盖：`ui_root.tscn` 可加载、托盘 9 个槽位齐全、内置 HUD（准星 / 血条 / 交互提示）自动注册、HudWidget 注册与 priority 排序、输入方案显隐、紧凑等级显隐、菜单打开隐藏 HUD / 关闭恢复、`register_external` 的 mod 正例与重复 id / 超尺寸反例、`debug_force_mobile` 模拟移动端时逻辑宽收敛到 900 且断点为 1、桌面恢复 1920 与断点 0、触屏控件实例化与摇杆注入 `move_forward`、模拟 `safe_insets` 下触屏控件避让安全区、暂停菜单 Resume / UI 缩放滑条接线、安全区字段。成功输出 `UI_SMOKE PASS` 与 `checks=N failures=0`（当前 43 项），进程退出码 0。

> headless 只验证脚本与布局树，不验证真实渲染、真机安全区与触屏手感；这几项仍需 Android/iOS 真机人工验证。

### 体素材质管线 headless 校验

体素材质的外观数据在 Godot 资源里（`bevy_client/voxel_material/`），像素来自 `tools/bake_voxel_materials.gd` 的烘焙产物 `tiles/*.res`。改了材质作者参数后必须重新 bake：

```bash
G=${GODOT_BIN:-/tmp/Godot_v4.7.2-stable_linux.arm64}
$G --headless --path godot-project --script res://test/gen_class_cache.gd
$G --headless --path godot-project --script res://tools/bake_voxel_materials.gd
$G --headless --path godot-project --script res://test/voxel_material_check.gd
$G --headless --path godot-project --script res://test/voxel_binding_check.gd   # 需要已构建 GDExtension
$G --headless --path godot-project --script res://test/voxel_shader_check.gd    # headless 也能跑 ShaderLanguage 解析
```

`voxel_material_check.gd` 断言库校验、block→面材质绑定、Texture2DArray 尺寸/层数/mip、参数 LUT 编码、草侧方向、normal 基线、ORM 通道、空气 alpha、bake 确定性与 10 层可扩展性，失败非零退出；`voxel_binding_check.gd` 再验 Rust 导出契约与 mesher 的 face_material_map 逐面重映射（需 GDExtension）；`voxel_shader_check.gd` 校验着色器语言层（uniform 集合 / render_mode / FRONT_FACING / alpha discard）——headless 的 dummy 渲染器仍会跑 ShaderLanguage 前端，能抓 Parse Error，但 SPIR-V 后端编译与真实观感仍需桌面/真机。CI 的 `godot` job 在导入后阻塞执行这三条检查，并额外重跑 bake 后 `git diff --exit-code` 校验资产与作者参数一致（见 `.github/workflows/ci.yml`）。

## CI 工作流

| 工作流 | 触发 | 内容 |
| --- | --- | --- |
| `ci.yml` | push 任意分支、PR | lint、测试矩阵、GDExtension debug、Godot debug 导出 |
| `release.yml` | `v*` tag 或手动 | release 构建与导出，汇总 GitHub Release |
| `perf.yml` | 改动体素相关路径的 PR 或 push 到 main | criterion 同机 A/B 加 gungraun 指令数 |
| `generate-android-keystore.yml` | 手动 | 生成 Android release keystore 并可写入 Secrets |

CI 的 job：

- `lint`：`cargo fmt --check` 与 clippy，当前非阻塞。
- `test`：Linux、Windows、macOS 三平台 `cargo test --workspace`。
- `gdext`：Linux x86_64、Linux arm64、Android 的 debug 动态库。
- `godot`：Linux x86_64、Linux arm64、Android APK 与 AAB 的 debug 导出。

runner 镜像并不统一：`lint`、`perf`、`test` 的 Linux leg、`gdext` 的 Android leg、`release` 的 Linux arm64 / Windows / Android leg 用 `ubuntu-24.04`；`gdext` 的 Linux 两腿、`godot` 导出 job 与 `release` 的 Linux x86_64 leg 用 `ubuntu-22.04`；`test` 另有 `windows-2022` 与 `macos-14`。Godot 由 `chickensoft-games/setup-godot` 安装。

> `docs/ci.md` 已按 2026-10-20 的 workflow 校对过；以后再改 workflow 时同步改它。

## 性能门禁

墙钟部分用同机 A/B，不用入库的绝对基线：

1. 用 `git worktree` 检出基线 commit。
2. 两侧各跑若干轮，顺序对调。
3. 按轮次配对算 `Δ = 当前 / 基线 - 1`，取各轮最小的 Δ。
4. 超过 `.github/scripts/perf/thresholds.json` 的阈值就让 job 失败。

阈值默认 15%，纳秒与微秒级基准放宽到 20% 到 30%。`single_edit/old_local_e2e` 是对照组，列入 ignore。

指令数部分：gungraun 在 Valgrind Callgrind 下统计指令数，与 CPU 无关，基线可跨 runner 复用，默认软阈值是涨幅超过 10%。

## 已知约束

- Android 已跑稳，发布矩阵转强门禁：`release.yml` 两个 Android leg 为 `experimental: false`，失败会阻断发布。
- Windows 用 MinGW 交叉编译，遇到加载兼容性问题可改 `windows-latest` 与 `msvc`。
- macOS 未纳入发布矩阵，`.gdextension` 保留了条目，导出预设缺失。
- clippy 与 instructions job 都是 `continue-on-error`，代码全绿后应去掉。
