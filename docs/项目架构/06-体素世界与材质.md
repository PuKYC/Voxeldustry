# 体素世界与材质

体素这块分三段：**存储与网格**（Rust 整数体素，`crates/voxel`）、**世界与游戏层**（Bevy 机制 + 内容）、**表现**（raw halo → Godot 侧矩形展开 + Texture2DArray 材质）。前两段是逻辑真相源，第三段只消费只读数据。

材质在 2026-10-22 改过一版所有权（V1 参数写死在 Rust → V2 外观归 Godot + 烘焙资产）。本文只写**当前生效**的契约，改版理由见文末「决策记录」。

## 四层职责

| 层 | 位置 | 职责 |
| --- | --- | --- |
| 存储与网格 | `crates/voxel` | SVO-DAG 存储、贪婪网格、矩形提取、LOD 四叉树、确定性存档 |
| 世界机制 | `game-engine/src/voxel` | `VoxVolume`、附着、编辑缓冲、脏集、懒生成、内容哈希、碰撞 |
| 网格机制 | `game-engine/src/presentation/voxel` | 重建计划、矩形打包、raw halo、增量缓存，纯函数库不注册插件 |
| 游戏内容 | `game-core/src/voxel` | Body、停靠、LOD 策略、地形生成与流式分块 |
| 材质表现 | `godot-project/bevy_client/voxel_material` | 材质外观、block→面绑定、烘焙瓦片、Texture2DArray + 参数 LUT |

## 存储：SVO-DAG

- `VoxTree<u8>` 是稀疏体素八叉树，u8 调色板，0 表示空气，也是 `VoxTree` 的默认值。
- 每个 chunk 是 32³，`CHUNK_DEPTH = 5`，`ChunkKey` 用整数坐标寻址。
- `VoxInterner` 做内容寻址去重与引用计数，预算 `DEFAULT_INTERNER_BUDGET_BYTES`。
- `VoxOps*` 系列 trait 提供批量写入、脏标记、状态查询。
- 存档（`io`）按结构序遍历，不使用 map 迭代序，保证同样数据写出同样字节。

**边界铁律**：这一层只用整数体素坐标，不知道 `voxel_size`。世界换算只发生在 `game-engine::voxel::volume` 的 `body_voxel` 与 `world_meters`。

## LOD 策略

| 项 | 值 |
| --- | --- |
| 最高 LOD | 3（`MAX_LOD`），对应深度 5 到 8 |
| 距离阈值 | 32 m、64 m、128 m（`LOD_DISTANCE_THRESHOLDS`） |
| 分块方式 | 受限四叉树，2:1 平衡 |
| 运行期配置 | `VoxelLodConfig`，Godot 经 FFI 可改 |

当前实现（`generate_block_at_lod` / `extract_raw_halo` / `append_skirts` 三阶段）：

1. **A · 按自身 LOD 生成**：LOD 大于 0 的块由 `generate_block_at_lod` 直接按粗格生成，不折叠 LOD0 数据。
2. **B · 同 LOD 邻接与自闭合**：块只与同 LOD 邻居剔除面，跨 LOD 一律按缺失处理，于是每块封自己的边。
3. **C · 接缝裙边**：`skirt_mask` 标记跨 LOD 错位面与无同 LOD 邻居的面，mesher 按块内判据补裙边，作为正确性安全网。

代价与现状：

- 接缝是台阶墙，不是洞。台阶只出现在远处 LOD 交界，实际观感无关紧要，已接受为已知代价（见 [[11-当前状态与风险]]）；若要压低台阶，走 LOD fade（`lod_fade_duration`，默认 0 = 关闭）或各向异性 LOD，不靠裙边。
- 自闭合后裙边在当前 extract 路径下是 no-op，保留它是为了切向轴回归测试与未来改动。

## 矩形与打包

贪婪网格输出 `RectInstance`，每个矩形是位置无关的整数描述符（8 字节）：

| 位 | 字段 | 位宽 |
| --- | --- | --- |
| 0-2 | orientation = plane * 2 + dir | 3 |
| 3-8 | slice | 6 |
| 9-13 | row | 5 |
| 14-18 | col | 5 |
| 19-24 | w | 6 |
| 25-30 | h | 6 |
| 31-38 | material | 8 |
| 39-46 | AO，四角各 2 bit | 8 |
| 47-63 | 保留 | 17 |

- 描述符本体 39 bit，AO 是向后兼容的纯扩展，旧消费端只读前 39 bit。
- 排序固定为 `(ChunkKey, plane, dir, material, slice, row, col)`，保证确定性。
- AO 角序 `i = cx | (cy << 1)`，与着色器 UV 一致。
- `material` 现在是**材质 id**（= Texture2DArray 的 layer）：mesher 按 Godot 给的 256×6 字节表把 block id 换成材质 id。同一矩形内材质必然相同（贪婪只在同 `plane/dir/material` 内合并），所以它天然适合做层索引。

## 表现通道：raw halo

体素块不传矩形流，传原始方块 id：

| 项 | 值 |
| --- | --- |
| 内部尺寸 | 32³ |
| halo 尺寸 | 34³，即内部 32 加两侧各一层 |
| 缓冲大小 | 39304 字节 |
| 下标 | `hx + 34 * (hy + 34 * hz)` |
| 值 | 方块 id，0 表示空气 |
| halo 内容 | 26 个同 LOD 邻块的一层边界 |

- `RawVoxels` 载荷把 34³ 缓冲交给 Godot，由 GDScript 侧调 gdext mesher 现算矩形。矩形一律留在内部 32³，不跨缝合并。
- `RawVoxelGroups` 载荷把同一 LOD 的多个块打成一个组件，每块各自一个子 `VoxelMeshNode`。
- 这条通道是唯一表现通道，载荷 code 8 与 9 只追加。
- GDScript 调 `mesh_voxel_halo(lod, blocks, skirt_mask, face_material_map)`：第 4 个参数是 Godot 生成的 256×6 字节面材质表（见下文「材质管线」）。

## 碰撞

- `physics` feature 引入 avian3d 0.7，开 `enhanced-determinism`。
- `VoxelCollisionPlugin` 按 chunk 构建碰撞几何，两种收集：全体素或外壳。
- `VoxelCollider` 与 `VoxelCollisionChunk` 跟随脏块更新，块卸载时清理。
- `game-core` 默认开 `physics`，无物理构建用 `--no-default-features`。

## 材质管线：多张 Texture2DArray 共享材质索引

矩形描述符里的 8 bit `material` 就是 **Texture2DArray 的 layer 索引**：多张同 depth / 同尺寸 / 同 mip 的平行数组分别承载 albedo、normal、ORM（可选 emissive），同一 layer 在四张数组里是同一个材质。数组是**全局共享**的，不是每块一份；不改几何、不改线格式、不增加 draw call、不增加 per-rect 内存。

### 结论与取舍

- **零几何成本**：`material` 字段本来就在每个矩形里，换语义不扩数据。varying 只有 4 个 float（`v_uv` 2 + `v_ao` 1 + `flat v_material` 1）；TANGENT / BINORMAL 用引擎内建，不占自定义 varying。
- **显存 ∝ 层数 × 尺寸²**：9 层 64² 三张（albedo + normal + orm，含 mip）约 **0.49 MB**，加 emissive 约 0.69 MB；128² 四张约 2.75 MB。层数是主要杠杆，64²→128² 是 4 倍成本。
- **真正的成本在片元**：标配路径 3 次采样 + 1 次 LUT `texelFetch`，720p 纹理带宽最坏约 0.72 GB/s；数组本体只有 0.5 MB 级，与区块数量无关。
- **硬件不跨层插值**：没有 atlas 那种「采样到隔壁材质」的串色问题，也不需要 padding。
- 与 LOD / 移动体无关：UV 用块局部坐标，`Ship` / `Automaton` 移动时贴图不滑动；乘 `2^lod` 让贴图世界尺寸跨 LOD 一致。

### 索引语义：layer == 材质 id

- 不用 block id 做层号：256 层固定，64² 三张约 13.97 MB，且同材质方块重复贴图（实际只用 9 个材质）。
- 用材质 id：层数 = 材质数，默认库 9 个，`VoxelMaterialLibrary.MAX_LAYERS = 64` 是自设上限；64² 三张约 0.49 MB。**同一 layer 在四张数组里表示同一材质**，这就是「共享同一个材质索引」的字面实现。
- 材质 id 就是 `materials` 数组下标，资源里没有 id 字段；`material_key` 只做稳定键 / 日志 / 对账。
- `layer_count` uniform 做夹取（官方文档建议不要在片元里调 `textureSize`），越界层不采样。
- 数组硬约束：同 depth、同尺寸、同格式族、同 mip 层数、同 wrap；一次 `create_from_images` 建立，首层决定尺寸与 mip。
- 扩展成本：新增材质 = 加一个 `defs/*.tres` 并追加到 `materials`（再 bake）；新增方块绑定 = 加一个 `VoxelBlockMaterial`。两者都不需要改 Rust 和 shader。

### 数组与格式

| 数组 | 格式 | 通道 | 说明 |
| --- | --- | --- | --- |
| `albedo_array` | RGBA8（**线性**） | RGB = basecolor，A = alpha 裁剪 | bake 时把 sRGB 作者色转成线性字节 |
| `normal_array` | RG8（线性，OpenGL +Y） | RG = 切线空间 xy，z 由引擎重建 | 只用 RG 通道；`normal_strength` 在 bake 时烘进 RG |
| `orm_array` | RGBA8（线性） | R = 材质 AO，G = roughness，B = metallic | 移动端标准打包，一张数组承载三个标量 |
| `emissive_array` | RGBA8（线性） | RGB = 自发光 | 没有自发光材质时**不建不绑**，片元跳过第 4 次采样 |

- 全部**不加 `source_color`**：`sampler2DArray` 的 sRGB 视图在 4.7 没有文档保证，加错 hint 直接编译失败；且 normal / orm 本来就是线性数据。作者色在 bake 阶段按 IEC 61966-2-1 转成线性字节，运行时按线性采样，输出阶段由引擎转回 sRGB。
- mip 由 `build_arrays()` 生成（`generate_mipmaps`，法线重归一化），bake 产物里不存 mip。
- 为什么 ORM 合成一张而不是三张：采样次数与带宽按数组数线性增长，而三个标量总是一起被 BRDF 使用。

### Godot 资源模型

目录 `godot-project/bevy_client/voxel_material/`：

| 文件 | 类 | 职责 |
| --- | --- | --- |
| `voxel_material.gd` | `VoxelMaterial` | 单个材质的作者参数 + `tiles: VoxelMaterialTiles` |
| `voxel_material_tiles.gd` | `VoxelMaterialTiles` | 烘焙后的 4 张 Image（线性），运行时只读 |
| `voxel_block_material.gd` | `VoxelBlockMaterial` | `block_key` + 六面材质 id（顺序 `[+x,-x,+y,-y,+z,-z]` = `plane*2+dir`） |
| `voxel_material_library.gd` | `VoxelMaterialLibrary` | 材质表 / block 绑定 / 构建与对账 |
| `voxel_material_arrays.gd` | `VoxelMaterialArrays` | 构建产物：3~4 张数组 + 参数 LUT + 层数 |
| `defs/<key>.tres` | — | 9 个默认材质定义 |
| `tiles/<key>.res` | — | 9 个烘焙瓦片资产（二进制 Image） |
| `voxel_material_library.tres` | — | 材质表 + block 绑定 + 构建参数 |

默认层序（下标即 layer）：stone / dirt / grass_top / sand / snow / wood / leaf / air / grass_side。草方块六面 = `[8,8,2,1,8,8]`（+Y 草顶、-Y 土、四周草侧）。

`VoxelMaterial` 参数（26 个，7 组，全部可导出）：

| 组 | 字段 | 说明 |
| --- | --- | --- |
| Identity | `material_key`、`display_name` | 稳定键 / 显示名 |
| Baked | `tiles` | bake 产物；运行时必须有 |
| Albedo | `albedo_texture`、`albedo_texture_srgb`、`albedo_color`、`albedo_pattern`、`pattern_secondary_color`、`pattern_scale`、`pattern_strength`、`pattern_band`、`pattern_seed` | 源纹理或程序化图案 + sRGB 作者色 |
| Normal | `normal_texture`、`normal_strength`、`normal_flip_green`、`normal_from_albedo` | 无法线图时从高度场生成 |
| ORM | `orm_texture`、`roughness`、`metallic`、`occlusion` | R = AO / G = rough / B = metal |
| Emission | `emission_texture`、`emission_texture_srgb`、`emission_color`、`emission_energy` | 黑色 = 不发光 |
| UV / Alpha | `uv_scale`、`alpha_scissor` | cutout 阈值，0 = 关闭 |

`VoxelMaterialLibrary` 关键 API：

- `validate()`：层数上限、`tile_size` 为 8..512 的 2 的幂、key 唯一、bake 产物存在且边长一致、`uv_scale` 是 1/256 的整数倍、block 面 id 不越界；
- `build_arrays(force)`：逐层 duplicate → mip → `Texture2DArray.create_from_images` + RGBAH 参数 LUT，成功才原子替换缓存；
- `validate_block_binding(block_names)`：与 Rust 导出的方块名**双向**对账，缺绑定直接 ERROR（否则会静默渲染成 material 0）；
- `build_face_material_map(block_names)`：256×6 字节，index = block×6 + face；一个方块都对不上时返回空表（Rust 走 identity 降级）。

### 烘焙管线（运行时不生成像素）

```
VoxelMaterial 作者参数（颜色 / 图案 / 粗糙度 / 可选 art PNG）
        │  godot --headless --path godot-project --script res://tools/bake_voxel_materials.gd
        ▼
tiles/<key>.res（VoxelMaterialTiles：albedo 线性 RGBA8 / normal RG8 / orm RGBA8 / emissive RGBA8）
        │  VoxelMaterialLibrary.build_arrays()（启动一次，主线程）
        ▼
albedo / normal / orm（/ emissive）Texture2DArray + RGBAH 参数 LUT
        │  VoxelMeshNode.apply_material_library()
        ▼
共享 ShaderMaterial（所有块同一个）
```

- 为什么产物是 `.res`（Image 资源）而不是 PNG：normal / orm 是线性数据，走 Godot 导入会被默认 sRGB / VRAM 压缩二次污染；`.res` 的 Image 不需要 import，编辑器 / headless / CI / 导出包行为一致。
- 美术输入仍是 PNG：bake 优先读 `res://art/voxel_materials/<key>_{albedo,normal,orm,emissive}.png`；该目录带 `.gdignore`，只做输入，不导入、不进导出包。
- 幂等：同样的作者参数 + seed，连续两次 bake 的 md5 不变；改参数或改 `tile_size` 后必须重新 bake，运行时校验 tiles 边长并报错。
- CI 用「重跑 bake 后 `git diff --exit-code`」把「改了参数忘了重烤」变成红灯（见 [[09-构建测试与CI]]）。

### 着色器与参数 LUT

一个 `ShaderMaterial` 服务所有层，逐材质标量不能靠普通 uniform，统一放进参数 LUT：

| 项 | 值 |
| --- | --- |
| 格式 | `Image.FORMAT_RGBAH`（RGBA 16F），width = layer_count，height = 1，无 mip |
| 采样 | `texelFetch(pbr_params, ivec2(layer, 0), 0)`，`filter_nearest, repeat_disable` |
| 编码 | `(uv_scale × library.uv_scale, alpha_scissor, emission_energy, 0)` |
| 用途 | 顶点取 uv_scale；片元取 alpha_scissor（cutout）与 emission_energy |

加逐材质标量 = 加一列（或换行布局）+ shader 读一行，不动数组分配与材质 schema 的其它部分。

`voxel_rect.gdshader` 的 16 个 uniform：

| uniform | 说明 |
| --- | --- |
| `rect_data` | 39 bit 矩形描述符（不变） |
| `albedo_array` / `normal_array` / `orm_array` | 线性数据，不加 `source_color` |
| `emissive_array` | 仅 `has_emissive` 时绑定与采样 |
| `pbr_params` | 参数 LUT |
| `layer_count` | 越界层夹取 |
| `has_emissive` | 跳过第 4 次采样 |
| `use_material_layers` | false = 库未就绪的中性灰兜底（避免默认 1×1 纹理导致整屏 discard） |
| `voxel_size` / `block_origin` / `block_lod` | 几何 |
| `ao_floor` / `ao_strength` / `ao_power` / `lod_fade` | 观感开关 |

片元顺序：`FRONT_FACING` 翻回背面法线 → 采样 albedo（含 alpha 裁剪）→ NORMAL_MAP（只写 xy）→ ORM → 可选 EMISSION → `AO_LIGHT_AFFECT = 1.0` → LOD fade discard（必须留在末尾）。

**UV 与 TBN**

- UV 用**块局部**坐标：`v_uv = vec2(cols, rows) × 2^block_lod × uv_scale`。用块局部而不是世界坐标，移动体上的贴图才不会滑动；数值范围也只有几百体素，远距离精度好。
- 乘 `2^lod` 让贴图的**世界尺寸**跨 LOD 不变；`32 × 2^lod` 仍整除 tile，块边界相位连续，所以跨矩形不 `fract` 也不接缝。
- 面族 UV 轴固定（与 `rect_corner` 的展开一致）：

| plane | 面 | u 轴 | v 轴 |
| --- | --- | --- | --- |
| 0 | ±X | +Z | +Y |
| 1 | ±Y | +X | +Z |
| 2 | ±Z | +X | +Y |

各向同性贴图无感；木纹 / 草皮边缘 / 箭头这类方向性素材必须按这个约定出图。

- TANGENT / BINORMAL 写「与面朝向无关的恒定轴」：TANGENT = plane 0 → +Z、其余 → +X；BINORMAL = plane 1 → +Z、其余 → +Y。不能写成 `cross(N, T)`——那样有一半朝向的 v 轴会被镜像。
- `cull_disabled` 下每个平面族必然有一半朝向被引擎当背面（引擎会做 `NORMAL = -NORMAL`），片元开头必须用 `if (!FRONT_FACING) NORMAL = -NORMAL;` 翻回来，否则那半面只剩环境光。
- `dir` 只翻法线、不换绕序，所以部分面上的贴图是镜像的；体素材质基本各向同性，这一点接受。

### Rust 契约

- `get_voxel_table()` 只返回两项：`voxel_size: float`、`block_names: PackedStringArray`（长度 256，下标 = block id，未知为空串）。GDScript 用 `block_names` 把 `VoxelBlockMaterial.block_key` 映射到 block id 并双向对账。
- `mesh_voxel_halo(lod, blocks: PackedByteArray, skirt_mask, face_material_map: PackedByteArray) -> PackedInt64Array`：第 4 个参数是 Godot 生成的 256×6 字节表（1536 B），mesher 逐矩形 `rect.material = map[block*6 + face]`。
- 长度不是 1536 时退化为 identity（材质 id = block id），绝不 panic；空表是 Godot 的显式降级信号。
- Rust 侧没有 `MaterialId` / `MATERIAL_NAMES` / `BlockDef.face_materials` / 材质外观字段 / 瓦片生成代码；`static_data::voxel` 只有方块 id、名字、solid 与地形 / 群系数据。
- 新旧扩展混装握手：GDScript 看 `get_voxel_table()` 是否含 `block_names`；旧扩展没有该键时 `VoxelMeshNode.mesh_supports_face_map = false`，按 3 参旧签名调用，避免逐块 `Invalid call` 导致体素完全不渲染。

### 显存与带宽

`单层字节 = S² × B × 4/3`（含 mip），`数组字节 = layers × 单层字节`。下表按十进制 kB / MB、9 层：

| 配置 | 尺寸 | 层数 | 数组 | 合计 |
| --- | --- | --- | --- | --- |
| 移动低配 | 32² | 9 | albedo + ORM | 约 98 kB |
| 移动标配 | 64² | 9 | albedo + normal(RG8) + ORM | 约 0.49 MB |
| 加自发光 | 64² | 9 | 再加 emissive | 约 0.69 MB |
| 桌面 / 高端 | 128² | 9 | 4 张 | 约 2.75 MB |
| 层数上限 32 | 64² | 32 | 3 张 | 约 1.75 MB |
| 对照：block id 做层 | 64² | 256 | 3 张 | 约 13.97 MB |

片元采样与带宽（720p = 921,600 px，1080p = 2,073,600 px，×1.3 overdraw；这是「每次采样都打到 DDR」的上限）：

| 档位 | 采样/片元 | 字节/片元 | 720p60 | 1080p60 |
| --- | --- | --- | --- | --- |
| 低（albedo + ORM） | 2 | 8 | 约 0.58 GB/s | 约 1.29 GB/s |
| 标配（+ normal RG8） | 3 | 10 | 约 0.72 GB/s | 约 1.62 GB/s |
| 加 emissive | 4 | 14 | 约 1.01 GB/s | 约 2.26 GB/s |

- 工作集只有「层数 × S² × B」：64² / 9 层时 albedo 与 ORM 各约 196 kB（含 mip）、normal 约 98 kB，合计约 0.49 MB；32² 低配约 0.12 MB。空间 / 时间相干 + mip 局部性会明显降低真实带宽，**以真机 profile 为准**。
- 结论：先控层数（9~32），再谈分辨率；压缩纹理的优先级低于减少层数与采样数。

### 移动端约束与裁剪

| 约束 | 结论 |
| --- | --- |
| 渲染器 | 数组在 Forward+ / Mobile 的 RD 后端都可用；安卓建议 Mobile（官方：Forward+ 在移动端支持但优化差） |
| Compatibility | 现有管线已依赖 `Texture2DRD` + `usampler2D`，本来就跑不了；数组不是新增的兼容性损失 |
| 层数上限 | GLES3 / Vulkan 规范保证最少 256 层，`MAX_LAYERS = 64` 是自设上限 |
| 采样器 | 片元纹理单元保证最少 16 个，这里用 3~5 个 |
| 格式 | RGBA8 / RG8 非压缩，移动端全支持；RG8 法线比 RGBA8 省一半带宽 |
| mipmap | 逐层 mip、线性 mip 过滤，不开各向异性 |
| tile-based GPU | layer 是 flat varying，不是逐像素分支；数组采样与 2D 采样同价 |
| varying | 自定义只有 4 个 float（TANGENT / BINORMAL 走内建） |
| 输出精度 | Mobile 是 RGB10A2、Forward+ 是 RGBA16F；高光与环境光需要在两个渲染器上分别校准 |
| 纹理压缩 | ASTC / S3TC 需要导入管线；当前 0.5 MB 级不值得，留 P2 |

裁剪顺序：

1. 无自发光材质时 `has_emissive = false`，不建第 4 张数组（当前默认状态）；
2. 低端 / 发热：`tile_size` 降到 32 重新 bake，配动态分辨率 0.7~1.0；
3. 远距离靠 mip；P2 可选「远处退化成平均色」省采样；
4. 不引入阴影 / IBL / SSAO（Mobile 限制 + 成本）；
5. 画质档（低 / 中 / 高 shader 变体）当前未做：单 shader + `has_emissive` 开关覆盖 3~4 次采样路径；等真机 profile 显示瓶颈再加变体。

### 已知边界 / 后续

- `.res` Image 资产不能在图像编辑器里直接改；美术工作流是「改 `art/` PNG → 重跑 bake」。
- 美术 PNG 要走 Godot 导入（压缩 / mip / 虚拟纹理）需要单独设计 import 预设与运行时读取方式，当前刻意绕开 import 以保证 headless / CI / 导出包一致。
- 纹理压缩（ASTC / S3TC）未做：64² × 9 层只有约 0.5 MB，等瓦片尺寸 / 层数上去再评估。
- `alpha_scissor` 只做 cutout，不做透明混合；水体等半透明材质需要新渲染通道。
- `uv_scale`（含库全局乘数）必须是 1/256 的整数倍，否则块局部 UV 不是整数、块边界出现接缝；`validate()` 会报错。
- `build_arrays()` 缓存签名基于资源实例 id：运行时资产只读没问题；编辑器里原地改 `tiles` 后必须 `build_arrays(true)`。
- 每个材质仍是单层贴图，不支持 UV 旋转 / 三平面映射。
- 后续可做：ORM 每材质恒定 → 上移顶点 + flat varying 省 1 次采样；LOD fade 关闭时拆「无 discard」变体救 early-Z；低 / 中 / 高 shader 变体。

## 决策记录：V1 → V2

V1（2026-10-22，同日被 V2 取代）的做法：材质参数写死在 `game-core/src/static_data/voxel.rs` 的 `MATERIAL_TABLE`（9 项），程序化瓦片在 Rust 生成，`get_voxel_table()` 把约 **441 kB** 的 `PackedByteArray`（palette + albedo / normal / orm / emissive）经 Variant 搬给 Godot；着色器是引擎 lit + 4 张 `sampler2DArray`；block→面绑定是 Rust 的 `BlockDef.face_materials[6]`。

推翻它的原因不是性能，而是它**不是管线**：

- 改一个颜色要改 Rust 常量 + 重编扩展 + 重启；
- 参数只有 color / roughness / metallic / emissive / pattern 六个，且是 u8 / 枚举，加参数要同时动 Rust、GDScript、shader；
- 接不了美术贴图，不能在检查器里调，不能热改，不能被 mod 覆盖；
- 「材质」同时承担像素数据与 GPU 资源装配两件事，职责全压在 Rust。

| 项 | V1 | V2 |
| --- | --- | --- |
| 材质参数 | Rust 常量（6 个，u8 / 枚举） | Godot `VoxelMaterial`（26 个导出字段） |
| 瓦片像素 | Rust 程序化生成，启动搬 441 kB | Godot bake 成 `tiles/*.res`，启动只 load |
| block → 面绑定 | Rust `BLOCK_TABLE.face_materials` | Godot `VoxelBlockMaterial` + 1536 B face map |
| 导出契约 | `voxel_size` / `material_count` / `palette` / `pbr{...}` | `voxel_size` / `block_names`（约 1.6 kB） |
| 新增材质 | 改 Rust + GDScript + shader | 加 `defs/*.tres` + 追加到 `materials` |
| 改颜色 | 重编扩展 | 改 `.tres` + 重跑 bake |
| 像素确定性 | Rust 单测 | bake 幂等（md5）+ CI 新鲜度门禁 |

V1 里仍然成立的早期决策（V2 原样继承）：

- **layer = 材质 id**，不是 block id；
- **光照走引擎 lit**，不自算 GGX；
- **颜色标准**：作者色是 sRGB，bake 时精确转线性 RGBA8，数组不加 `source_color`；
- **per-face 材质首版就要**：草方块 `[8,8,2,1,8,8]`；
- 默认库 9 个材质（含 `air` 占位与 `grass_side`），8 个方块绑定。

## 参考资料

- Godot `Texture2DArray`：无层间插值、每层独立 mip、不需要 atlas padding。
- Godot 着色器语言：`sampler2DArray`、`flat` varying、`texture()` / `texelFetch`、`FRONT_FACING`、`source_color` 的 sRGB 语义。
- Godot 法线贴图：OpenGL 风格（+Y），只用 RG 通道；`Image.generate_mipmaps()` 重归一化。
- Godot 渲染器：Forward+ / Mobile 都走 RenderingDevice；Mobile 输出 RGB10A2、Forward+ RGBA16F；Forward+ 在移动端不推荐。
- 仓库内实现：`godot-project/bevy_client/shaders/voxel_rect.gdshader`、`godot-project/bevy_client/entity/voxel_mesh.gd`、`godot-client-ext/src/presentation_bridge.rs`、`game-core/src/presentation/voxel_mesh.rs`、`godot-project/tools/bake_voxel_materials.gd`。
